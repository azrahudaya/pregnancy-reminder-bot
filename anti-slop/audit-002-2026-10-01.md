# Audit 002, UX & UI RemindCare (pregnancy-reminder-bot)

**Repo:** `/home/fuudaya/Projects/pregnancy-reminder-bot`
**Tanggal:** 1 Okt 2026
**Metode:** pembacaan kode statis (index.js, lib/admin-ui.js, lib/admin-settings-page.js). Server produksi berjalan, tapi audit ini membaca sumber, bukan click-through runtime (R-35 belum dinyatakan PASS secara runtime).
**Lensa:** skill antislop (core), antislop-ui, antislop-human, antislop-layoutmobile. Rujukan aturan ditulis `R-XX`.

## Ringkasan

Sebagian besar temuan audit 26 Sep 2026 (39 admin + 25 UX) sudah dibereskan: XSS, bind 0.0.0.0, brute force login, CSRF, CSP+nonce, kolom status tabel, baris tabel jadi link nyata, aria-pressed filter, error banner, dsb. Audit ini mencatat yang masih tersisa.

| Severity | Jumlah |
|---|---|
| HIGH | 1 |
| MED | 3 |
| LOW | 4 |

## HIGH

### 1. Onboarding terima nama/umur/kehamilan apa pun (data korup, terlihat di "info")

**Bukti**, `handleOnboardingAnswer()` index.js:5304-5306. Cabang `else` (untuk `name`, `age`, `pregnancy_number`) langsung `updates[question.field] = text.trim();` tanpa validasi. Pertanyaan di index.js:156-157 (`name`, `age`).

Akibat nyata di DB produksi: `name = "halo"`, `age = "12"`. Pesan `info` mengirim judul "Info Penting RemindCare - halo". Perintah `start`/`menu` yang diketik saat onboarding juga tersimpan sebagai nama.

**Kenapa gagal:** R-17 (angka tanpa validasi), C-1 (intentionality), dan ini data kesehatan yang dipakai untuk menghitung usia kehamilan/HPL, jadi nilai sampah merusak seluruh alur hilir.

**Fix:** validasi per field: `name` tolak kata perintah (start/menu/halo/batal) dan panjang < 2 atau > 40; `age`/`pregnancy_number` wajib angka dalam rentang wajar (mis. 15-60 untuk umur, 1-15 untuk kehamilan). Kirim pesan koreksi spesifik, jangan simpan apa pun.

## MED

### 2. Ikon ✅/❌ dipakai untuk fakta netral di pesan info

**Bukti**, `buildUserInfoMessage()` index.js:1010 dst. Contoh dari output nyata: "Status input persalinan: ✅ Data persalinan tidak sedang diisi" (fakta netral diberi ikon sukses), dan pola `withStatusIcon()` (index.js:938) memakai ✅/❌ untuk ya/tidak.

**Kenapa gagal:** `antislop-human` "Color-Only Feedback" (makna lewat ikon/warna untuk fakta netral), R-27 (state harus akurat). ✅ pada "tidak sedang diisi" membingungkan.

**Fix:** ✅/❌ hanya untuk ketercapaian goal (target tercapai/belum). Untuk fakta ya/tidak pakai teks polos atau ikon netral.

### 3. Persona bot tidak konsisten: aku / Bunda / Ibu / kamu campur

**Bukti:** `QUESTIONS[0]` index.js:156 "aku RemindCare", `getDisplayName()` index.js:810 fallback "Bunda", `buildUserInfoMessage` dan alur persalinan pakai "Ibu". Belum dinormalisasi jadi satu suara.

**Kenapa gagal:** C-1 (intentionality), R-31 (keputusan copy harus punya alasan). Untuk audiens ibu hamil, campur "Bunda" dan "Ibu" membingungkan.

**Fix:** tetapkan satu persona (bot = "aku/RemindCare", pengguna = "Ibu") dan ganti semua string, termasuk fallback `getDisplayName` dari "Bunda" ke "Ibu".

### 4. Font Google (pihak ketiga) dimuat di 4 halaman admin berisi data pasien

**Bukti:** index.js:1864-1866 (login), 1913-1915 (dashboard), 2417-2419 (detail), lib/admin-settings-page.js:88-90 (pengaturan). Semua `<link>` ke `fonts.googleapis.com` + `fonts.gstatic.com`.

**Kenapa gagal:** C-4 (resilience, gagal render offline), R-38/C-5 (membocorkan IP/UA admin ke Google; mitigasi Referrer-Policy: no-referrer). Panel internal data kesehatan sebaiknya nol dependensi pihak ketiga.

**Fix:** self-host `Plus Jakarta Sans` (2-4 file woff2) dan hapus preconnect pihak ketiga. CSP sudah memuat `fonts.googleapis.com`; sesuaikan ke `font-src 'self'`.

## LOW

### 5. Tautan CSV detail user rusak saat waId kosong

**Bukti:** index.js:2434 `href="/admin/api/users/${encodeURIComponent(waId || "")}/export.csv"` menghasilkan path `/admin/api/users//export.csv` bila waId kosong. Route (index.js:6813) menolak waId kosong, jadi ini dead link hanya saat parameter hilang.

**Fix:** sembunyikan tautan CSV bila waId kosong, atau jangan render halaman bila waId tidak valid.

### 6. Border tombol `.btn-danger` di bawah 3:1

**Bukti:** lib/admin-ui.js:109 `.btn-danger { border-color: var(--line-strong) }` = `#c9cad1`, kontras ~1.5:1 terhadap putih. Batas kontrol interaktif seharusnya 3:1 (WCAG 1.4.11). Teksnya merah `--bad` (kontras tinggi), jadi masih terbaca, tapi tepi tombol tidak memenuhi ambang non-teks.

**Fix:** `border-color` gelapkan ke minimal `#767680` (3:1) atau pakai `--control-border`.

### 7. Filter fase di mobile scroll horizontal tanpa petunjuk

**Bukti:** lib/admin-ui.js:224 `.seg { width: 100%; overflow-x: auto; }` di bawah 900px. Segmented filter 5 tombol jadi scroll horizontal. Ini contained scroll yang sah, tapi tanpa bayangan tepi/petunjuk scroll pengguna tidak tahu ada opsi lebih banyak di kanan.

**Fix:** tambah gradien tepi atau buat filter wrap (flex-wrap) daripada scroll, supaya semua opsi terlihat.

## Yang sudah benar (jangan diubah)

- R-02 (em dash): 0 kemunculan `—` di seluruh repo.
- R-25 (kontras teks): `--muted #71717a` pada putih 4.84:1 (lolos 4.5). Teks utama `#18181b`, badge ok/warn/bad semua di atas 6:1.
- R-32 (keyboard): `:focus-visible` 2px outline di semua kontrol, tidak ada `outline: none`. Baris tabel user = link `<a>` nyata. Dialog/toggle bisa Escape (details.pop).
- R-27 (state): dashboard punya error banner + retry, per-section guard, empty state dengan sebab, `aria-busy` di tabel. Halaman detail punya `page-note` + 404 terbedakan.
- R-35 (bisa dijalankan): server produksi aktif dan halaman admin ter-render (diperiksa via curl di sesi ini).
- A11y: `scope="col"`/`scope="row"`, `aria-pressed` filter, `role="status" aria-live` pada toast, `aria-label` pencarian.
- Keamanan: CSP+nonce, CSRF+origin check, rate limit login, password hash scrypt + file mode 0600, bind 127.0.0.1 default.
